react-native-filament 2.0 is a rewrite on [Nitro Modules](https://nitro.margelo.com). The React components keep their names and most of their props, so most apps migrate by updating dependencies, replacing the APIs listed below and following the type errors that remain.

## Requirements

- New Architecture only, on React Native 0.83.
- [`react-native-nitro-modules`](https://nitro.margelo.com) 0.37.
- [`react-native-gesture-handler`](https://docs.swmansion.com/react-native-gesture-handler) 2.30 or later, only for `useOrbitGestures`.
- [`react-native-worklets`](https://docs.swmansion.com/react-native-worklets) 0.7 replaces `react-native-worklets-core`. Use its babel plugin:

```js title="babel.config.js"
module.exports = {
  presets: ['module:@react-native/babel-preset'],
  plugins: ['react-native-worklets/plugin'],
}
```

When the app uses Reanimated 4, keep `react-native-reanimated/plugin` instead; it includes the worklets plugin.

Add the new peers next to react-native-filament 2.0:

```npm
npm i react-native-nitro-modules@0.37 react-native-worklets@0.7
```

react-native-filament no longer uses `react-native-worklets-core`. Remove it unless another library in the app needs it.

## Rendering is native

v1 ran a JS render callback every frame and called `beginFrame`/`render`/`endFrame` from it. In 2.0 the render loop is native: animations, camera manipulators and physics run natively on Filament's render thread, and SharedValue bindings update through worklets, so none of them need the React Native JS thread. Like v1 it renders every frame by default; `renderMode="on-demand"` on `FilamentScene` or the Engine renders only after something changed. A `renderCallback` still exists for per-frame render-thread work. While it is set, it keeps the Engine rendering every frame, even in `on-demand` mode.

`FrameInfo` fields are renamed: `timestamp` → `timestampNs`, `passedSeconds` → `elapsedSeconds` and `timeSinceLastFrame` → `deltaSeconds`; `startTime` is removed and `frameIndex` is new. `RenderCallbackContext.useRenderCallback(callback, deps)` becomes `useFrameCallback(callback, deps)`, whose callback is a worklet.

<ApiTabs>
<Declarative>

```tsx
<FilamentScene renderMode="on-demand">
  <FilamentView style={{ flex: 1 }} renderCallback={renderCallback}>
    {/* ... */}
  </FilamentView>
</FilamentScene>
```

</Declarative>
<Imperative>

```tsx
engine.renderMode = 'on-demand'
const subscription = await runOnRenderThread(engine, () => {
  'worklet'
  return engine.addOnFrameListener((frame) => {
    // per-frame work on the render thread
    return true // keep rendering in on-demand mode
  })
})
```

</Imperative>
</ApiTabs>

See [Rendering](/docs/rendering#render-modes) and [Threading](/docs/threading#per-frame-code).

## Changed and removed APIs

### `useWorkletEffect`, `useWorkletCallback`, `useWorkletMemo` and `workletContext`

They keep their 1.x parameters; `useWorkletCallback`'s type parameters are now `<Args, Result>`, so explicit type arguments from 1.x, such as `useWorkletCallback<typeof fn>(...)`, need updating. They now run on the Engine's render thread through react-native-worklets instead of worklets-core:

- `useWorkletEffect` and `useWorkletCallback` take their dependencies from the values the worklet captures, as in 1.x.
- `useWorkletMemo` takes an explicit dependency list.
- `useFilamentContext().workletContext` has `runAsync` and `createRunAsync`.

Only the Filament calls inside them change:

```tsx title="Before"
const { transformManager } = useFilamentContext()
useWorkletEffect(() => {
  'worklet'
  transformManager.setEntityScale(entity, [2, 2, 2], false)
})
```

```tsx title="After"
const { transformManager } = useFilamentContext()
useWorkletEffect(() => {
  'worklet'
  transformManager.setScale(entity, [2, 2, 2])
})
```

A function returned from the effect runs on the render thread before the next run and on unmount, and may capture any render-thread value. In 1.x, a cleanup that wasn't a worklet ran on the JS thread:

```tsx
useWorkletEffect(() => {
  'worklet'
  const subscription = world.addOnCollisionListener((events) => handle(events))
  return () => subscription.remove()
})
```

`workletContext` queues its jobs behind the render-thread work that components have already submitted in the current commit:

```tsx
const { scene, workletContext } = useFilamentContext()
const entityCount = await workletContext.runAsync(() => {
  'worklet'
  return scene.entityCount
})
```

`useRenderThreadEffect`, `useRenderThreadCallback` and `useRenderThreadMemo` do the same with an explicit dependency list. Outside of components, use `runOnRenderThread(engine, worklet)`, which resolves with the worklet's result. The Worklets example in the example app uses all four 1.x APIs. See [Threading](/docs/threading#the-1x-worklet-hooks).

### `useSyncSharedValue`, `useDerivedValue` and worklets-core shared values

Pass Reanimated SharedValues straight to the props that accept them, and derive them with Reanimated's own `useDerivedValue`:

```tsx title="Before"
const animatedRotationY = useSharedValue(0) // Reanimated
const rotationY = useSyncSharedValue(animatedRotationY)
const rotation = useDerivedValue<Float3>(() => {
  'worklet'
  return [0, rotationY.value, 0]
})
```

```tsx title="After"
import { useDerivedValue, useSharedValue } from 'react-native-reanimated'

const rotationY = useSharedValue(0)
const rotation = useDerivedValue<Float3>(() => [0, rotationY.value, 0])
// <ModelInstance index={0} rotate={rotation} />
```

Updates reach the render thread from the UI runtime directly, with no JS thread work and no React re-render. To read a SharedValue in render-thread code, bind it:

```tsx
const intensity = useValueBinding(intensitySharedValue)
const renderCallback = useCallback(() => {
  'worklet'
  lightManager.setIntensity(sun, intensity?.value ?? 0)
}, [intensity])
```

### `useBuffer` and `FilamentBuffer`

Loaders take a `{ uri }` or an `ArrayBuffer`. A `{ uri }` is read natively, so its bytes never pass through JS.

```tsx title="Before"
const buffer = useBuffer({ source: require('./material.filamat') })
const material = useWorkletMemo(() => {
  'worklet'
  return buffer == null ? undefined : engine.createMaterial(buffer)
}, [buffer])
```

```tsx title="After"
const material = useDisposableResource(
  () => engine.loadMaterial({ uri: Image.resolveAssetSource(require('./material.filamat')).uri }),
  [engine]
)
```

Components such as `Model`, `Skybox`, `EnvironmentalLight` and `BackgroundImage` accept a `require()`d asset, a URI string, `{ uri }` or an `ArrayBuffer`.

### `withCleanupScope`, `release()` and `isValid`

Every native object has `dispose()`. Disposing an owner disposes what it owns (a model's instances and players, a physics world's bodies), and `engine.shutdown()` resolves once everything is destroyed. Components and hooks dispose what they create on unmount.

### `FilamentScene` view options

View options are per view in Filament, so they move to `FilamentView`:

```tsx title="Before"
<FilamentScene ambientOcclusionOptions={{ enabled: true }}>
  <FilamentView style={{ flex: 1 }} />
</FilamentScene>
```

```tsx title="After"
<FilamentScene>
  <FilamentView style={{ flex: 1 }} ambientOcclusionOptions={{ enabled: true }} />
</FilamentScene>
```

Imperatively, set them on the target's `View` on the render thread. See [View options](/docs/rendering#view-options).

### Transparency

`FilamentView` is opaque by default and uses a `SurfaceView` on Android. Set `transparent` where v1's default `enableTransparentRendering` showed the views behind:

```tsx
<FilamentView style={{ flex: 1, backgroundColor: 'lightblue' }} transparent />
```

### Transforms

Transform props are absolute and StrictMode safe: the local transform is `translate · rotate · scale`, after the unit-cube fit when `transformToUnitCube` is set, and after the entity's own transform for `EntitySelector`. `multiplyWithCurrentTransform` is removed; nest `ModelInstance` inside `Model` to compose transforms, as in v1's examples.

`TransformManager` takes values instead of host objects:

| 1.x | 2.0 |
|---|---|
| `setEntityPosition(entity, position, multiply)` | `setTranslation(entity, position)` |
| `setEntityRotation(entity, angle, axis, multiply)` | `setRotation(entity, quaternionFromAxisAngle(axis, angle))` |
| `setEntityScale(entity, scale, multiply)` | `setScale(entity, scale)` |
| `getTransform(entity).translation` | `getTransform(entity)[12..14]` (column-major `Mat4`) |
| `updateTransformByRigidBody(entity, body)` | create the body with `entity` |

With `multiply` set to `false`, the 1.x setters replaced the whole local transform; the 2.0 setters replace only their part and keep the rest. For 1.x's `multiply` set to `true`, multiply the new matrix by `getTransform(entity)` yourself and write the result with `setTransform`.

For per-frame transforms, write a `TransformBinding` from any thread, such as a Reanimated worklet or a `renderCallback`:

```tsx
const binding = useTransformBinding(rootEntity)
const renderCallback = useCallback(({ elapsedSeconds }: FrameInfo) => {
  'worklet'
  const [x, y, z, w] = quaternionFromAxisAngle([0, 1, 0], elapsedSeconds)
  binding?.setRotation(x, y, z, w)
}, [binding])
```

### Animations

`Animator` plays animations natively through an `AnimationPlayer`; it accepts a SharedValue `animationIndex`, cross-fades with `transitionDuration`, and adds `loop`, `speed` and `time` for scrubbing. For imperative control, `useAnimationPlayer(instance)` returns the player.

### Camera manipulators and gestures

`useCameraManipulator` takes `homePosition`, `targetPosition`, `upVector`, `orbitSpeed` (radians per point) and `zoomSpeed`. `useOrbitGestures(manipulator)` returns a Gesture Handler gesture that orbits, zooms and returns home; pass the manipulator to `Camera`, which sizes its viewport.

1.x's `orbitHomePosition` is now `homePosition`, and `orbitSpeed` and `zoomSpeed` are numbers instead of arrays. The default home position moved from `[0, 0, 8]` to `[0, 0, 4]`; pass `homePosition: [0, 0, 8]` to keep 1.x framing.

<ApiTabs>
<Declarative>

```tsx
function OrbitView({ manipulator }: { manipulator: CameraManipulator }) {
  const gesture = useOrbitGestures(manipulator)
  return (
    <GestureDetector gesture={gesture}>
      <FilamentView style={{ flex: 1 }}>
        <Camera cameraManipulator={manipulator} />
      </FilamentView>
    </GestureDetector>
  )
}

function Scene() {
  const manipulator = useCameraManipulator({ homePosition: [0, 0, 8] })
  return manipulator == null ? null : <OrbitView manipulator={manipulator} />
}
```

</Declarative>
<Imperative>

```tsx
const manipulator = engine.createOrbitManipulator({ homePosition: [0, 0, 8] })
await runOnRenderThread(engine, () => {
  'worklet'
  camera.followManipulator(manipulator)
})
// Report the view's size in points, for example from onLayout:
manipulator.setViewport(width, height)
// useOrbitGestures(manipulator) works with this manipulator too.
```

</Imperative>
</ApiTabs>

See [Camera](/docs/camera#orbiting-with-gestures).

### Recording

`useRecorder` returns a `Recorder` that renders the scene offscreen on a fixed clock. `record(frameCount)` resolves with the MP4's URI, replacing v1's `startRecording`, per-frame `renderFrame` and `stopRecording`:

<ApiTabs>
<Declarative>

```tsx
const recorder = useRecorder({ width: 720, height: 1280, fps: 60 })
const uri = await recorder?.record(60 * 5)
```

</Declarative>
<Imperative>

```tsx
// On an Engine dedicated to recording: its view targets pause while it records.
const recorder = await runOnRenderThread(engine, () => {
  'worklet'
  const created = engine.createRecorder({ width: 720, height: 1280, fps: 60 })
  created.setScene(scene)
  created.setCamera(camera)
  return created
})
const uri = await recorder.record(60 * 5)
```

</Imperative>
</ApiTabs>

Animations, bindings and frame callbacks advance by exactly `1 / fps` per recorded frame. Give the camera the video's aspect with `<Camera aspect={720 / 1280} />`.

### Physics

Physics objects belong to a world, which steps itself with the Engine's frames and moves the entities its bodies are bound to:

| 1.x | 2.0 |
|---|---|
| `useWorld(0, -9.8, 0)` | `useWorld({ gravity: [0, -9.8, 0] })` |
| `useBoxShape(x, y, z)` | `useBoxShape(world, [x, y, z])` |
| `useStaticPlaneShape(nx, ny, nz, c)` | `useStaticPlaneShape(world, [nx, ny, nz], c)` |
| `useRigidBody({ world, mass, origin, shape, id })` | `useRigidBody(world, { mass, position, shape, id, entity })` |
| `world.stepSimulation(...)` in a render callback | automatic; `autoStep: false` and `world.step(deltaSeconds)` to step manually |
| `collisionCallback` | `world.addOnCollisionListener(events => keepListening)` |

### Values and types

- `Entity` is a number instead of `{ id }`.
- String unions are kebab-case: `'FXAA'` → `'fxaa'`, `'LOW'` → `'low'`, `'focused_point'` → `'focused-spot'`, `'disable_deactivation'` → `'never-sleep'`.
- `Mat4`, `Aabb` and quaternions are plain arrays and objects, not host objects.
- Options are plain objects; the `create*Options()` helpers are removed.
- Light intensities are `intensityLux` and `intensityLumens` in the imperative options; the `Light` component keeps `intensity`.

### Other changed APIs

- `useFilamentContext()`: `view` is `View | undefined` and is set only inside a `FilamentView`, which also provides `target`. `renderer`, `nameComponentManager` and `choreographer` are removed.
- `useModel()`: a loaded model has `model` instead of `asset`, and the `shouldReleaseSourceData` option is removed.
- `FilamentScene`: the `config` and `frameRateOptions` props are removed. To cap how often a view renders, use `targetFrameRate` on `FilamentView`.
- `useRecorder(options)` returns the `Recorder`, or `undefined` until it exists, instead of `{ recorder, swapChain }`. `bitRate` is optional.
- `useRecorderRenderLoop(recorder, render, deps)` takes a dependency list, and `render` receives a `FrameInfo` and returns nothing.
- `setLogger` and `getAssetFromModel` are removed. The `AABB` type is now `Aabb`, with `center` and `halfExtent` but no `min` or `max`.

### Threading

Methods that touch Filament run on the render thread and throw an error whose message starts with `FilamentThreadError` when called from another thread, instead of racing with rendering. Each method's documentation names its thread; see [Threading](/docs/threading).
