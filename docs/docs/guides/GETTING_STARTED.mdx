## Requirements

- React Native 0.83 with the New Architecture.
- iOS 15.1 or later, Android 7 (API 24) or later.
- Android renders with Vulkan 1.1 where the device supports it and with OpenGL ES 3.0 otherwise; pass `backend` to choose.

## Installing the library

1. Install react-native-filament with its two required peers, [Nitro Modules](https://nitro.margelo.com) and [react-native-worklets](https://docs.swmansion.com/react-native-worklets):

```sh
npm i react-native-filament react-native-nitro-modules react-native-worklets
```

2. Add the worklets babel plugin. If the app uses Reanimated 4, its plugin already includes it.

```js title="babel.config.js"
module.exports = {
  presets: ['module:@react-native/babel-preset'],
  plugins: ['react-native-worklets/plugin'],
}
```

3. Install the pods. The first `pod install` and the first Android build download the prebuilt Filament binaries from GitHub, verify their checksums and cache them for every later build:

```sh
cd ios && pod install
```

[Reanimated](https://docs.swmansion.com/react-native-reanimated) and [Gesture Handler](https://docs.swmansion.com/react-native-gesture-handler) are optional. Every animatable prop accepts a Reanimated `SharedValue`, and `useOrbitGestures` returns a Gesture Handler gesture.

### Expo

react-native-filament works in Expo development builds (it is not part of Expo Go). After installing, run `npx expo prebuild` or `npx expo run:ios`.

## Configure Metro

Let Metro bundle 3D assets next to your code:

```js title="metro.config.js"
const { getDefaultConfig, mergeConfig } = require('@react-native/metro-config')

const defaultConfig = getDefaultConfig(__dirname)

module.exports = mergeConfig(defaultConfig, {
  resolver: {
    assetExts: [...defaultConfig.resolver.assetExts, 'glb', 'ktx', 'filamat'],
  },
})
```

:::info
Models load from glTF binaries (`.glb`). Convert other formats (glTF, OBJ, FBX) with Blender or an online converter.
:::

## Render your first model

A scene needs:

- 🏞️ a view to draw into, `<FilamentView>`;
- 💡 light, otherwise everything is black, for example `<DefaultLight>`;
- 📦 a model, `<Model>`;
- 📹 a camera, `<Camera>`.

```tsx
import { Camera, DefaultLight, FilamentScene, FilamentView, Model } from 'react-native-filament'

export function MyScene() {
  return (
    <FilamentScene>
      <FilamentView style={{ flex: 1 }}>
        <Camera />
        <DefaultLight />
        <Model source={require('./drone.glb')} transformToUnitCube />
      </FilamentView>
    </FilamentScene>
  )
}
```

`<FilamentScene>` creates the Engine, a scene and its camera, and disposes them when it unmounts. Components below it that render nothing on screen, like `Camera` and `Model`, configure that scene. Render regular React Native views on top of a `FilamentView` with absolute positioning instead of inside it.

The scene renders natively on Filament's render thread: animations, camera manipulators, SharedValue-driven props and physics run there without JS, and a scene that does not change does not render again.

## Imperative API

Everything the components do is available on the native objects, which you can use directly or mix with the components through `useFilamentContext()`:

```tsx
import { Filament, NativeFilamentView, runOnRenderThread } from 'react-native-filament'

const engine = await Filament.createEngine({})
const target = await engine.createViewTarget(view, {})
const model = await engine.loadModel({ uri: modelUri }, {})
await runOnRenderThread(engine, () => {
  'worklet'
  const scene = engine.createScene()
  scene.addModel(model)
  target.setScene(scene)
})
```

Methods that touch Filament run on the Engine's render thread; [Threading](./THREADING.mdx) explains which thread each method expects.
