## Shared values

react-native-filament runs on [`react-native-worklets`](https://docs.swmansion.com/react-native-worklets/), the worklet runtime behind Reanimated 4.
Every prop that accepts a shared value takes a reanimated shared value directly, so you can drive it with `withTiming`, `withSpring`, `useDerivedValue` and the rest of reanimated's API:

```jsx
import { Model, ModelInstance } from "react-native-filament";
import {
  useDerivedValue,
  useSharedValue,
  withSequence,
  withSpring,
  withTiming,
} from "react-native-reanimated";

// Drive the animation with reanimated
const rotationY = useSharedValue(0);
const rotation = useDerivedValue(() => [0, rotationY.value, 0]);

const spin = () => {
  rotationY.value = withSequence(withSpring(Math.PI * 2), withTiming(0, { duration: 0 }));
};

return (
  <Model source={DroneGlb} transformToUnitCube>
    <ModelInstance index={0} rotate={rotation} multiplyWithCurrentTransform={false} />
  </Model>
);
```

Whenever the shared value changes on the UI runtime, react-native-filament applies the new value on the Filament runtime.

## Reading shared values in the render callback

Worklets you pass to react-native-filament (render callbacks, `useWorkletEffect`, `useWorkletCallback`) run on the Filament runtime, not on reanimated's UI runtime.
Reading `sharedValue.value` there works, but it synchronizes with the UI runtime on every read. Keep those reads out of hot paths, or mirror the value into a
[`createSynchronizable`](https://docs.swmansion.com/react-native-worklets/docs/memory/createSynchronizable) from `react-native-worklets` if you need it every frame.
